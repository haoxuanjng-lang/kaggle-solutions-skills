# 长期路线

## 已交付：0.1

固定版本的比赛索引、正文读取、来源链、21 张种子方法卡、研究到执行的交接、离线检索、
安装、测试与更新 PR 流程。把研究覆盖与档案覆盖分别计数。

## 下一阶段：0.2，优先加深真实使用反馈

- 用用户下一场实际比赛完成研究交接，积累本地和云端执行证据。
- 依据实际问题补全更多表格、时序、图像、音频、文本、推荐与 agent 反例；数量不是有效性指标。
- 在官方数据说明或作者代码确认后增加人工任务/验证标签，减少模态猜测。
- 对最常用方法补读作者代码，与报告交叉核对；保留报告/代码版本冲突。
- 维护一组真实检索请求，量化词法检索遗漏，再决定是否需要 embeddings/混合检索。

完成标准：至少有实际使用记录能解释为何新增或修订这些资源。不要为了达到卡片数量
而把尚未阅读的标题变成方法事实。

## 后续阶段：0.3，证据和维护可追踪

- 将实验输出通过明确映射导入方法证据，先 dry-run review 再更新知识。
- 记录来源再次读取时的内容变更/不可用状态，支持卡片的影响分析。
- 支持结构变化的 schema migration 与版本发布包。
- 有足够实际需求时再引入多来源更新和语义检索。

## 维护安排

周度自动任务只检查上游档案并创建 review PR。读新报告、代码审核、方法推断与版本发布
由实际用户任务驱动。每次比赛结束优先沉淀关键决定、真实负结果和资源边界。

项目默认放在私有 GitHub 仓库，便于先积累个人研究。以后若公开，先检查是否包含私人
实验/账户信息或未授权材料，再决定发布范围；skill 核心本身保持可独立分发。
